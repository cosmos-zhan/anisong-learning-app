# Project instructions

Formal scope and acceptance: docs/requirements.md (lyrics) and docs/piano-requirements.md (piano P0). Only this project; never write cosmos-zhan/Aria.
Use feature/* or fix/* branches and PRs after initialization. Every delivered modification, including CSS-only edits, must pass the complete App gate: npm run android:check (frontend type/lint/tests/build, emitted-app checks, Capacitor sync, native unit tests, debug APK assembly). Record real results and verify the final APK version matches the delivered commit. If native tooling is blocked, continue independent work but label the APK build incomplete; do not claim delivery passed. Do not merge without user acceptance.
Lyrics use original-track seconds outside the native clip adapter. Piano uses PPQ=480 musical ticks and an AudioContext-clock tempo map. Never simulate audio progress. Keep async operations cancel-safe. Never put tokens, private lyrics/audio, keystores, node_modules or generated dist in Git.
Read docs/delivery.md and docs/known-issues.md before continuing. Reuse the .openai/hosting.json Sites ID. Cloudflare Pages is preferred after authorization. No unrequested features and no unauthenticated assertions of successful deployment/CI/APK runs.

Android debug signing recovery: before generating a new debug key after a workspace reset, try to recover the user-private Anisong-debug-signing-20261019.zip backup and restore debug.keystore to the Android user directory. Never commit the key or password to GitHub. Changing the signing key prevents in-place updates and loses local practice data if an uninstall is required.

Version deliveries: the user wants APKs downloadable from GitHub Releases. For every new app version, update package.json and the lockfile root version, increase .github/android-preview.json versionCode, and push the current release branch. Require the complete App check and the public APK/signature/media checks before publishing a Pre-release; verify the returned Release and its actual APK asset URL. Never publish private-media or private test APKs to this public repository. Same-version documentation changes must not overwrite an existing release. Read docs/android-previews.md; preserve fixed signing via the repository Secret when configured and explicitly report any install/signing limitation. Keep the root README a project homepage; put chronological validation/delivery records in docs and release notes.
