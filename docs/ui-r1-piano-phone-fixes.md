# Android 截图反馈修复（0.3.5）

依据用户2026-10-19提供的准备页、竖屏和横屏练习截图。0.3.4的编译/DOM通过不代表已通过手机显示验收；本批不复用那一结论。

## 对应问题与改动

| 截图问题 | 原因与本批处理 |
| --- | --- |
| 参数标题居中、每行单独圆框、按钮被推到屏外 | `.info-row strong`继承全局右对齐与表单按钮边框。准备页改成专用行样式，左侧标题/说明、右侧值/箭头；四行共一张卡片，无重复圆框。应用式44px标题栏，缩短顶部，保存说明和次级设置移到进入按钮之后。 |
| 短横屏只剩两小节 | 原来按谱面高度小于84px自动减为两小节，兼容提示还会进一步占高度。现在每页固定四小节；翻页/播放跟随仍按真实小节。 |
| 音符缩成中间一小块 | 整个SVG按可用高度缩小，兼容谱下尤其严重。现在谱表间距最低保留9px（自然排版单位的0.9倍）；空间不足时在谱区滚动，谱字/点击层/音名保持同一比例，显示滑动提示。兼容提示改在标题区域，不再占一条谱面行。 |
| 琴键太薄、横屏整体比例失调 | 旧五行布局先扣掉标题/控制/状态，再把余高按4:3分配，短屏键盘很薄。现在四行：44px标题、余高谱面、44px控制、至少112px琴键（上限200px，随视口高调整）。普通状态为无障碍播报；错误、模式阻塞和下一休止操作仍可见，不挤入无声隐藏状态。 |
| 旋转/浏览器可见高度变化 | 使用visualViewport高度（无该API时innerHeight），监听其resize；保留范围和速度。原有旋转暂停语义继续保留，绝不假播放。 |

OSMD排版容器使用独立1024px逻辑宽度，避免初始化时继承尚未完成布局的1px框。真实乐谱数据、轨道和播放时间线不改写。未复现截图中Android端为何切到兼容引擎，不能宣称这一异常已经根治；本批确保兼容路径也保留可读比例，反馈新增可见视口/窗口高度/像素比，可连同已有渲染错误码继续定位。

## 验证门槛与边界

- 核心回归包括准备页真实样式级联（左对齐与无嵌套圆角）、320→390可见高度变化、琴键最低高度、四小节稳定分页、兼容路径及原有真实播放逻辑。
- 生产ESM在不提供Node process/require/Buffer的独立DOM运行环境中执行，检查精细SVG、真实合成器调度、交互和全部谱面页；私有默认曲有35页，公开合法示例2页。并不等同于浏览器排版/字体/听音验收。
- 每次交付必须执行 `npm run android:check`：类型、Lint、全套测试、production构建、钢琴和歌词产物交互检查、Capacitor同步、5项原生测试与debug APK。最终APK核对提交号、版本、签名及内置三项素材，CI亦执行同一完整门槛。
- 当前没有可用浏览器控制技能或物理Android，未声称截图像素或手机听音通过。手机结果优先于本地尺寸计算。

## 手机验收

1. 网页或新版APK核对0.3.5与当前提交号。进入春日影→钢琴准备：四行标题应靠左，右侧值/箭头齐右，没有内层圆框；进入按钮前不再有一段长存储说明。
2. 横屏：琴键明显比0.3.4高，黑键有按住区域；谱页显示1–4、5–8、9–12。浏览器地址栏展开/收起、旋转均检查一次。
3. 谱区若出现滑动提示，左右/上下滑动看同一页，不应缩成居中的缩略图。点可见小节应从该真实小节试听，四小节范围循环、暂停/重练/速度仍正常。
4. 若显示兼容谱面，确认仍是四小节、字号可读；点重试。若始终不能恢复精细谱，在反馈中复制包含renderer与viewport的报告，连同截图提供。
5. 等待弹对：错键不推进、对键推进；休止下一步和模式不兼容的解释按钮仍可见。多指按/放不得卡音。
