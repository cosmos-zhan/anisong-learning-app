# 反馈闭环

播放器右上角「反馈问题」。选择 Bug / 交互建议，填写描述、复现步骤、预期行为，阅读完整报告；可以编辑任何内容、取消诊断复选框。复制报告失败时长按报告全选。GitHub 按钮只打开预填草稿，由你登录后确认 Submit new issue。

默认诊断含 SHA、分支、构建时间、UA、选中行号、原曲起止时间、速度、循环和播放器状态。没有歌曲名、歌词文本、文件路径、URI、录音或音频内容。截图需在 GitHub 编辑器手工添加，请自行检查是否含私密信息。报告按钮不能访问你的 GitHub Token。

仓库没有创建 / 授权前，可以复制完整报告回 ChatGPT，Issue 链接暂不能实际提交。GitHub 仓库就绪后闭环：

1. 在手机预览发现问题并提交 Issue。
2. 让 Work 读取 Issue #编号，恢复仓库，新建 fix 分支。
3. 修复、补适当的回归测试，push 并开 PR，关联 `Fixes #编号`。
4. CI 通过后打开 Cloudflare 在 PR 贴出的预览 URL，在手机重做步骤。
5. 确认后合并 main，稳定网页自动更新。原生改动再手动运行 APK workflow。

尚未真实跑通 Issue→PR→预览复测的账号闭环，不应声称已经验收。
