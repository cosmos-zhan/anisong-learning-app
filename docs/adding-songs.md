# 新增可下载歌曲

当前默认目录：<https://anisong-media-source.woolly-mochi-2205.chatgpt.site/catalog.json>。

歌曲文件和程序分开发布。更新这个在线目录后，现有 0.6.1 App 联网打开下载管理或点击刷新即可看到新歌，通常无需更新 APK。内置春日影元数据仅作初始显示与网络失败时的回退；不要为了加歌只修改内置 JSON。

## 用手机提供素材

把以下文件及歌曲标题交给维护者，例如在当前工作会话附上文件，并说明“加入默认下载列表”：

| 内容 | 要求 |
| --- | --- |
| 音频（必需） | 推荐 MP3；当前服务单文件最大 25 MiB |
| 歌词（可选） | UTF-8 `.lrc`，有时间戳，最大 128 KiB；与音频版本匹配 |
| 乐谱（可选） | `.mxl`、`.musicxml` 或 `.xml`，最大 4 MiB；不是 PDF 或图片 |
| 显示标题 | 歌名及需要区分的演唱版本，例如“春日影 · CRYCHIC” |

只有音频也能加入列表；学唱需要匹配的 LRC，学谱需要 MusicXML / MXL。维护者负责检查解析、生成目录、上传、合并目录并验证一键下载。无需你在手机手算 SHA-256、编辑 JSON 或输入下载访问码。

当前默认服务按所有者要求公开读取，因此加入默认目录的歌曲文件也可公开下载。上传仍需独立管理员权限，App 和公开仓库不保存管理员凭据。所有者现在可用[私人上传台](https://anisong-upload-console.woolly-mochi-2205.chatgpt.site)选择文件上传，或解析网易云分享链接后点击“上传到在线曲库”；详见[网易云导入](netease-import.md)。Android App 中的网易云入口只导入本机。

上传台使用独立受限凭据和带 ETag 的单曲原子合并接口；不会直接覆盖整个目录。下方是保留的底层管理员整体发布流程，日常加歌应优先使用上传台。

## 维护者发布步骤

1. 读取并备份线上最新 `catalog.json`，保留全部已有歌曲。新增歌曲使用唯一且稳定的 `id`；同一歌曲替换文件时保留 `id`、提高 `revision`。
2. 在 Git 忽略的私人目录准备源文件。文件名使用英文字母、数字、点、下划线或短横线，例如 `my-song.mp3`；不要使用空格或中文文件名作为当前服务的对象名。
3. 用现有脚本生成真实大小和 SHA-256。脚本只复制文件并生成目录，不上传，也不会自动合并旧目录：

   ```json
   {
     "title": "Anisong 在线素材",
     "songs": [{
       "id": "my-song",
       "title": "我的歌曲 · 演唱版本",
       "revision": "20261023-1",
       "audio": "/private/my-song.mp3",
       "lyrics": "/private/my-song.lrc",
       "score": "/private/my-song.mxl"
     }]
   }
   ```

   ```bash
   node scripts/create-media-catalog.mjs private-media/source.json private-media/generated
   ```

4. 先将输出的媒体文件逐个上传到现有服务的 `PUT /api/admin/files/<文件名>`。文件名必须是脚本生成的“真实 SHA-256 前 16 位 + 连字符 + 原文件名”。请求使用独立 `ADMIN_TOKEN` 的 Bearer 鉴权，并设置 `X-Content-SHA256` 为请求体的完整 SHA-256；凭据只经安全环境或隐藏输入提供，不放进聊天正文、源码、终端日志或客户端。
5. 将生成目录中的新歌条目合入第 1 步的完整目录；同 ID 更新时替换该条目，新增时追加。再次读回线上目录，确认没有其他维护者的并发改动，再上传完整 `catalog.json` 到同一接口。**目录 PUT 是整体替换，不是追加；直接上传只有新歌的目录会让旧歌从在线列表消失。** 当前接口没有条件写入保护，目录发布必须串行进行。
6. 最后读回公开目录及每个新文件，核对大小、SHA-256 与 CORS，并在 App 刷新列表。管理员凭据不用于 App 下载。

服务会在保存目录前检查引用文件已经存在，且大小与 SHA-256 匹配；所以必须先上传文件、最后更新目录。当前服务不提供删除接口；不要为了新增歌曲重新部署旧的静态私人源模板或替换现有 Site。

目录遵循 [素材格式](media-downloads.md)：`id` 为 1–80 位小写字母、数字、短横线，首位为字母或数字；标题最多 120 字符，非空 `revision` 最多 80 字符。音频必需，歌词和乐谱可省略；目录最多 100 首、512 KiB。当前托管服务的 25 MiB 单文件限制比 App 一般音频限制 30 MiB 更严格。

## 上线后验收

1. 在使用默认源的 App 下载管理中刷新，新歌与原有春日影都应存在；自定义源用户需要切回默认源。
2. 直接点击新歌“下载到本地”，不出现访问码输入，真实进度完成后在“已下载”中可见。
3. 进入学唱，确认真实音频播放、歌词可选句；有乐谱时进入学谱，确认声部与小节解析正常。
4. 关闭素材网络后重新载入，确认本地音频、歌词和乐谱仍可读取。Android 还需实际设备离线重开验收；浏览器模拟 Android Origin 不能替代真机验证。
5. 若是同 ID 新 revision，确认页面提示可更新，用户主动重新下载后才替换本机资料；刷新目录和检查程序更新均不自动覆盖本地编辑。

默认春日影已有真实线上浏览器一键下载、离线 42 句歌词 / 140 小节谱面和 MP3 解码进度的 CI 门禁；每首新歌仍需单独验收，不能沿用春日影的通过记录。脚本 `verify-live-download-browser.mjs` 当前针对春日影，不是所有歌曲的自动遍历器。
