# 钢琴横竖屏实测修复（0.3.6）

本轮使用真实 Chromium 对 production dist 渲染和截图，检查画面后修改；不是 jsdom 尺寸推算或设计稿截图。入口、歌曲管理、真实 AudioContext 播放与练习状态沿用现有工程。

## 复现与修复

1. Chromium 的 XMLSerializer 在序列化整个 Document 时保留源 XML 声明。原代码再拼一条声明，缓存声部再次截取分页时产生两条声明，精细渲染失败并退回兼容谱面。现在只序列化 documentElement，再添加一条声明。
2. 竖屏使用可换行的四小节页，窄手机每行一小节，较宽竖屏每行两小节；横屏保持四小节横排。系统间为音名辅助留出空间。密集乐段可以在谱面内滚动，不压缩成缩略图。
3. 竖屏琴键高度限制为160–220 CSS px，谱面使用剩余空间。短横屏（高度≤360）把标题与播放控制放在同一行，归还44px给谱面；琴键仍≥112px。实际安全边距和 visualViewport 高度继续参与布局。
4. 谱面按宽、高一起等比缩放，最低0.75倍；全部可见时不再因追随底部音名把谱号、调号滚出顶部。固定宽度临时容器在排版后改为真实 SVG 宽度，移除空白横向溢出。
5. 声音启用入口放入键盘区，避免挤掉标题；窄屏／短横屏的音名和八度操作收进“更多”。黑键显示简短升号音名，完整等音名称保留于无障碍标签。

## 可重复的浏览器检查

```sh
npm ci
npx playwright-core install --with-deps chromium
npm run build
npm run test:browser
```

可用 `BROWSER_EXECUTABLE_PATH` 指定已安装的 Chromium / 官方 Chrome Headless Shell。受管容器不允许 Chrome 普通版的本地 singleton socket 时，本轮使用官方 Headless Shell 155.0.8059.84，保持真实 Chromium 的 DOM、SVG、字体、canvas 和 Web Audio 实现。未替换渲染器或用计时动画代替音频。

## 验证和验收边界

核心测试153项，原生测试5项，完整 App 门槛为 `npm run android:check`：类型、Lint、Vitest、production build、产物交互检查、Capacitor sync、clean、原生单测、debug APK。每次交付都执行此门槛，CSS修改也不跳过。浏览器回归单独运行，网页CI自动保存截图。

自动浏览器检查可证明真实渲染、触键事件和音频调度，不能代替 Android16 物理手机的听音、触控手感、系统字体缩放、特定 WebView 和旋转动画验收。极密集小节与更矮的分屏仍可能需要在纸面内滑动；兼容渲染器仅是故障时的简化谱面，不等于精细排版。

## 手机复测

1. 设置页确认0.3.6（APK为0.3.6-test.1），进入春日影钢琴练习。首次点击“启用声音”，或直接点小节试听。
2. 竖屏查看1–4小节应分行，琴键不占半屏；横屏应见四小节横排。短横屏的播放按钮在顶部右侧，其他横屏在谱面下方。
3. 点第2小节，听到真实试听后暂停；连续旋转两次，范围仍是第2小节，播放保持暂停。再按琴键，检查按住发声、松开发音释放。
4. 翻到9–12、73–76和137–140小节，检查谱号与五线谱没有被顶部切掉。密集页面可滑动，不能用缩小到不可读替代。
5. 如仍异常，用“更多→反馈”附屏幕截图；报告自动包含实际版本、视口、谱面后端、声部、范围与速度。APK沿用0.3.5测试签名，可覆盖更新并保留练习状态。
