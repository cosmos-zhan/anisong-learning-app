# UI R1 钢琴第二批：参数面板与练习准备

版本 0.3.2，接续 [第一批](ui-r1-piano-batch1.md)。对照 R1 的 `pianoPrep`、`pianoMode`、`pianoTracks`、`labels`、`blocked` 与 `pianoMore` 场景，完成钢琴参数设置这一条操作链。歌词布局、歌曲详情、首页卡片和反馈两步预览属于后续批次。

## 已实现

| 入口 | 本批行为 |
| --- | --- |
| 钢琴准备 | 显示当前歌曲与真实小节数 / 声部数 / 初始速度；四行摘要分别进入练习方式、声部轨道、小节范围、速度面板。辅助标记与循环为次级操作。 |
| 标题旁的练习方式 | 只展示自动试听、等待弹对、自由弹奏三项与说明。换模式停止声音，保留范围和速度，不自动开始。 |
| 右上齿轮 | 打开独立声部与轨道面板。只包含乐器声部、原始轨道、当前轨摘要及适用的单音简化 / 返回原轨动作。 |
| 控制带的音名 / 唱名 / 标记关闭 | 只打开音名、固定唱名、关闭三个选项；同时作用于谱面与琴键。固定唱名 C = Do，与调号无关。 |
| 更多 | 保留反馈、歌曲资料、歌词学唱、返回准备四项；去除混合参数表单。 |
| 等待弹对与原轨冲突 | 就地解释限制，提供主动选择最高音单音、继续原轨试听、换声部轨道的路径。绝不静默简化原轨。 |

模式、声部、速度和标记为即时设置，选择后可继续检查，点关闭 / 遮罩 / 返回回到练习。小节范围继续采用第一批的“预览后确认”语义。切换参数面板内容不新增历史层级；标题变化时焦点回到面板，返回一次关闭当前面板。

在原轨上请求等待弹对时，若有和弦或其他不支持的内容，先显示解释，尚不修改当前模式。此时返回可取消请求，原轨和模式不变。用户明确选最高音后才切到该练习轨与等待模式；最高音轨保留原始轨的身份和返回入口。已经在等待模式时改回不兼容原轨，则保留真实选择并提示冲突，不自动删音或开始播放。

切换到小节更少的声部会安全裁剪范围并显示原因。练习状态继续通过原有本机存储恢复。反馈快照新增 `labels`，与声部序号、谱表、轨道投影、范围、速度、模式和真实版本一起报告。

## 自动验证

本地 `npm run check` 已通过：18 个测试文件、135 项测试、类型检查、Lint 与 production 构建；构建后 ESM DOM 检查也通过了真实谱面、小节试听节点调度、全部独立参数面板及导航回归。

`tests/piano-refinement.test.tsx` 新增五项交互回归，覆盖：

- 准备页只有摘要；各参数面板内容独立。
- 模式切换保留范围与速度；虚拟琴键错误输入不前进，正确输入才前进，按放接到实际控制器音频接口。
- 辅助标记作用于键盘，保存后恢复，并出现在真实反馈报告中。
- 和弦冲突取消、明确选择最高音、返回原轨的流程；原轨试听调度完整和弦音符。
- 较短声部裁剪范围、保留速度，恢复所选声部和标记时不自动发声。

构建后 `scripts/verify-built-app.mjs` 直接执行产出的 ESM 与懒加载谱面渲染器，补充模式 / 声部 / 标记独立面板检查。它使用 jsdom 与仪器化 Web Audio 节点，不能替代手机视觉、实际听音和多点触控验收。Android 构建继续执行原生单元测试并校验安装包版本、签名和资源；最终结果见对应提交的 GitHub Actions 和本次交付记录。

## 手机验收

1. 打开春日影 → 钢琴准备。确认四项参数以摘要显示；点练习方式不会再出现速度或声部表单，点声部只看当前乐器和轨道。
2. 进入练习并横屏。选第5–8小节、0.5倍，切换自动试听 / 自由弹奏，再回自动试听；范围和速度保持，均需主动点播放。
3. 点击当前模式选择等待弹对。若当前原轨含和弦，应直接看到原因；按返回取消后仍是原轨与原模式。
4. 再次选择等待弹对，明确选“改练最高音（单音）”。点“开始等待”；错误琴键应停留，正确琴键才前进。休止仍需点“下一步（休止）”。
5. 打开齿轮，检查当前声部、谱表、声部编号及最高音状态。点返回原轨，应解释与等待模式的冲突；选择继续自动试听原轨，再主动播放，检查能听到原轨和弦。
6. 音符辅助依次切到固定唱名、关闭、音名；检查真实谱面与琴键。关闭辅助仍可弹奏，音高不应改变。
7. 刷新 / 重新打开 App，检查乐谱、声部、范围、速度、模式、标记恢复，且没有自动发声。打开反馈，确认版本及 `labels` 与实际状态一致。
8. 每个面板内测试关闭、遮罩、浏览器返回及 Android 系统返回；应先关面板，再次返回才离开练习。

## 边界和后续

本批没有可用的浏览器控制技能或物理 Android16，未完成像素对齐、软键盘、系统手势、听感和实际触控验收。声部与轨道仍使用手机原生选择器；仅当前轨道发声，不宣称多乐器合奏。准备页外层品牌栏和底部导航仍待整体页面层级批次统一。

后续 Work 从 `feature/piano-p0` 恢复，执行 `npm ci`、`npm run check`、`node scripts/verify-built-app.mjs`。Android 先构建前端与 Capacitor 同步，再用 JDK21 / SDK36 运行原生单元测试与 debug 构建。用户媒体只进入私有测试站与私有 APK，继续排除于公开 GitHub。
