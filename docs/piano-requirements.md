# Anisong Learning App — 钢琴学谱模块功能与实施方案

**文档类型：** 可交付给 ChatGPT Work 的功能任务书  
**版本：** Piano P0 v1.0（2026-10-15）  
**项目关联：** `cosmos-zhan/anisong-learning-app`（如仓库已存在，直接在现有项目中迭代；勿创建平行仓库，勿修改 `cosmos-zhan/Aria`）  
**开发环境：** ChatGPT Work + GitHub；用户主要通过 Android 16 手机浏览器验收，没有本地开发电脑。

## 一、目标与边界

为动画歌曲增加**钢琴学谱模式**。用户能够导入结构化乐谱，在横屏界面中查看谱子、选择一个或连续多个小节循环试听，并在屏幕下方的虚拟钢琴上自己弹奏。重心是对喜欢的歌曲进行**按需、按段、可重复**的学习，不做强制闯关评分。

**P0 必须形成的闭环：** 导入示例 MusicXML → 选择练习声部 → 查看五线谱 → 点击小节开始试听并循环 → 改变速度、暂停 → 切换“等待弹对”模式 → 触摸对应琴键逐音推进 → 保存练习范围/进度 → 手机预览、提交反馈。

**P0 不承诺：** 从混合歌曲音频自动转钢琴谱；PDF/图片识谱；原曲音频与谱子的自动同步；完整双手专业钢琴教学；外接 MIDI 键盘；复杂乐谱所有符号的无损播放；官方歌曲和商业曲谱内置下载。

## 二、入口与完整用户路径

1. 在歌曲详情页点击【钢琴学谱】。若尚无乐谱，进入【导入乐谱】页，可选择 MusicXML（`.musicxml` / `.xml` / `.mxl`）。同时提供可直接体验的、许可明确的内置示例乐谱。
2. 导入后展示歌曲名、调号、拍号、小节数和可用声部。用户选择要学习的声部，默认选择主旋律；多声部乐谱必须明确当前选择，避免将整份管弦谱视作钢琴独奏。
3. 点击【开始练习】，优先进入横屏布局。浏览器无法自动强制横屏时，提供【旋转手机】提示与手动适配方案，不能因旋转受限而完全不能使用。
4. 默认显示五线谱、试听模式、1.0×、循环已开启，起始选择第 1 小节或上一次保存的小节。点击某小节，选择该小节并开始试听；歌曲播放只由当前谱面生成的钢琴音负责，不依赖外部歌曲录音。
5. 点击【选择范围】，依次点击起始、结束小节，例如第 5 小节和第 8 小节，则循环第 5–8 小节（包含起止小节，保留其中休止符和时值）。
6. 点击【等待弹对】，播放器停在目标音，屏幕高亮目标音符和对应琴键；用户实际触摸正确琴键才推进到下一音符/事件。此模式不自动按节拍推进。
7. 可随时暂停、从范围起点重练、切换模式、调整速度和琴键显示区域；离开页面前自动保存最后练习的小节范围与设置。

## 三、横屏界面设计（P0）

```text
┌──────────────────────────────────────────────────────────────────┐
│ ← 返回  曲名 / 当前声部       五线谱 | 简谱 | 唱名      ⚙ 反馈   │
├──────────────────────────────────────────────────────────────────┤
│  乐谱区（约屏幕高度 45%）                                         │
│  小节 5          小节 6         小节 7          小节 8              │
│  ♫ ♪ ♩  ...      ♫ ♪ ...        ...             ...               │
│  [正在演奏的音符高亮]   [所选循环范围淡色标记]                     │
│                                                                  │
│  练习：5—8 小节    [选择范围]  [单小节]  [重练]                    │
├──────────────────────────────────────────────────────────────────┤
│ [试听] [等待弹对] [自由弹]    ◀  ▶/Ⅱ  ■    循环☑   0.75×          │
├──────────────────────────────────────────────────────────────────┤
│  虚拟钢琴（约屏幕高度 35–40%）                                    │
│  [黑键]    [黑键]         [黑键]     [黑键]     [黑键]               │
│  | C4 | D4 | E4 | F4 | G4 | A4 | B4 | C5 ...                     │
│  ← 左移八度       [当前目标：G4]         右移八度 →                │
└──────────────────────────────────────────────────────────────────┘
```

**交互原则：** 乐谱与琴键同时可见；控制区尽量紧凑，琴键足够宽；页面不被弹窗挡住；手机手指按下后应立即有按键高亮和声音反馈。支持多点触控和黑键优先命中，避免滑动键盘与按琴键手势互相误触。

- **乐谱区：** 可横向滚动/随进度自动跟随。点击小节选择；所选范围与当前播放音符用不同视觉样式。若已选范围，点击“重练”回到起点。
- **琴键区：** 默认显示约 1–2 个八度（随手机宽度自适应），可左右移动音域；P0 支持独立触键发声、按住持续、松开释放，支持至少常见双指同时按键；显示 C4 等音名。
- **竖屏：** 提供简化浏览与导入界面；演奏时建议横屏。不能假设浏览器总能锁定方向。
- **播放按钮：** 在“试听”模式播放/暂停谱面；在“等待弹对”模式用于进入/暂停待弹状态；“自由弹”模式无自动谱面推进。

## 四、核心功能与验收行为

### F01 乐谱导入和声部选择（P0）

- **首选 MusicXML**：`.musicxml`、`.xml`，支持 `.mxl`（压缩 MusicXML）。加载后展示标题、调号、拍号、速度、小节数和声部清单；文件无标题时使用文件名。
- 导入失败有明确原因，例如无效 XML、缺少可播放音符、格式不支持；绝不能空白屏。保留最近导入乐谱的元数据及本地持久化副本（视文件权限与存储限制实现）。
- 同一乐谱的多个乐器/声部可切换，P0 练习对象限定为**一个选定声部中的单声部旋律轨道**；若包含和弦、复杂复调、跨声部等暂未支持元素，明确提示并展示尽可能完整的原谱，不能静默丢失重要音符。
- MIDI 作为 **P1 可选导入**：能够转换成音符事件，但 MIDI 不是完整记谱格式，缺少连线、谱号、准确拼写等信息，需要量化和修谱，不能承诺导入后五线谱一定准确。

### F02 三种记谱显示（分阶段实施）

- **P0：五线谱**，显示调号、拍号、小节线、音符时值、休止符、必要的升降号；当前音符高亮。至少保证 P0 验收样例显示无错位。
- **P0：唱名辅助**，提供在音符附近显示固定唱名（Do、Re、Mi）或音名（C、D、E）的开关；须在界面说明“固定唱名”与调式意义不同。
- **P1：简谱切换**，对已验证的单旋律谱显示 1–7、升降号、上下八度点和时值，区分首调简谱（1=调内主音）与固定音名；遇到未支持的复杂符号，明确提示而不是错误转换。
- **P1：独立唱名谱视图**，如有必要再增加；P0 的唱名叠加已足够验证学习体验。

### F03 小节选择与循环（P0）

- 单击任意小节：选择这一小节；试听模式下从该小节起点开始，选中范围默认立即循环（可在设置关闭自动开始）。
- 点击【选择范围】进入区间选择，再点击起点小节和终点小节：形成**闭区间**，如 5–8 小节。允许反向点击，系统自动排序。
- 选中区间是乐谱上的“节拍/音符位置”，不是歌曲录音的绝对秒数；自动播放所用秒数由速度与拍号计算。速度变化后区间仍是相同小节。
- 范围包含休止符。到结束小节边界后回到起始小节，重复次数可选无限循环（P0 默认）；可关闭循环以便只试听一次。
- 提供跳转前后小节、重练、暂停/继续，以及练习区间持久化。切换声部时保留小节范围（若新声部小节数不足则安全裁剪并提示）。

### F04 虚拟钢琴（P0）

- 白键、黑键可触控；正确的半音映射，按下立即显示按键状态和发声；松开后声音释放，禁止永久挂音。
- 多点触控至少满足两个音同时按下与释放；快速连击同一键能正确触发，不产生卡音。
- 触摸按键与拖动琴键音域使用明确分开的交互区；不允许误触浏览器页面滚动。
- 默认音色为钢琴。允许先采用简易合成音色实现功能，然后替换成许可合规的钢琴采样；禁止直接把商业采样打包到公共仓库。

### F05 三种练习模式（P0）

1. **试听模式**：App 按乐谱自动播放钢琴旋律，同时谱面音符和琴键联动高亮；用户可暂停、变速、循环。此模式不需要用户按琴键。
2. **等待弹对模式**：高亮下一个目标音；用户触碰该音对应键后推进到下一事件。弹错键可提示正确音，但不扣分、不强制重来；在休止符位置显示“休止”并允许通过“下一步”推进或自动跳过（规则固定并在界面说明）。P0 仅严格验收单音旋律；和弦可预留多音输入事件接口，暂不要求完整练习判定。
3. **自由弹奏模式**：虚拟键盘始终可演奏，谱子可手动滚动，用户自行决定是否参考乐谱，不自动打分。

从一种模式切换到另一种模式时，须停止上一模式的自动音频任务，保留选中小节，新的模式从区间起点开始；不能出现两个声音引擎叠加播放。

### F06 速度、节拍和视觉同步（P0）

- 支持至少 0.5×、0.75×、1.0×、1.25× 的**相对谱面速度**，改变乐谱自动播放的 tempo，而非改变原曲人声的音高；钢琴音符的绝对音高不变。
- 音符的时值、休止符、附点、连音线等应通过结构化事件控制。P0 对简单常规拍号乐谱必须可靠；变速后保证播放指针与听到的音符基本同步。
- 允许显示当前速度与目标音。节拍器/预备拍可作为 P1，但内部时间模型必须预留拍点和 tempo 变化信息。
- 音频初始化受移动浏览器用户手势限制时，提示用户点一次“启用声音”；不得虚假显示音频已正常播放。

### F07 本地练习进度与反馈（P0）

- 保存歌曲/乐谱、当前声部、小节范围、模式、速度、记谱设置和最后练习时间；首次可用浏览器本地存储，无须云账号。
- 沿用歌词模块的 GitHub Issue/反馈流程。反馈文本自动带上构建版本号、浏览器/设备类型、乐谱格式、声部、所选小节、练习模式和速度；绝不默认上传原始歌曲/谱子文件。
- 用户可在同一项目中从“学唱”切到“学谱”，但 **P0 两者暂不要求自动时间同步**；歌曲的练习记录和钢琴的练习记录独立维护。

## 五、核心对象与跨模块复用

- `Song`：歌曲的通用元数据。可关联本地歌词/音频，也可关联一个或多个独立乐谱。
- `Score`：格式、标题、声部、调号、拍号、tempo map、结构化小节。
- `NoteEvent`：稳定 ID、声部 ID、小节 ID、开始节拍位置（ticks）、时值（ticks）、MIDI pitch、谱面拼写（音名字母、升降号、八度）、休止符/连音线/和弦归组信息。
- `PracticeRange`：`startMeasureId` 与 `endMeasureId`（闭区间）及选定声部；不以绝对播放秒数作为唯一标识。
- `PianoPracticeSession`：练习模式、速度、重复次数、最后位置和时间。

音频调度与 UI 高亮必须读取同一份结构化事件，避免各自独立计算导致逐渐失步。MusicXML 的反复记号、跳房子、弱起小节、速度变化、跨小节连音线等情况要有统一处理策略；P0 测试未覆盖的复杂符号，导入时须提示“暂不完整支持”，不能悄悄按普通小节顺序误播。

## 六、实现建议（非强制栈）

- **前端**：复用现有 React + TypeScript 网页预览和 GitHub 工作流，不另起仓库。
- **五线谱渲染**：优先评估 OpenSheetMusicDisplay（OSMD），它可加载/绘制 MusicXML、具有游标能力；**它不是可直接依赖的完整免费音频播放引擎**，必须单独实现音符调度、声部选择和声音输出。
- **钢琴音频**：Web Audio API 或 Tone.js（Sampler/PolySynth）；先确保触键响应和多音播放，再优化音色与延迟。
- **简谱**：基于通用 `NoteEvent` 自行转换及绘制，避免把 MIDI 数值直接当作正确的简谱或五线谱音名。
- **Android**：先实现真实手机浏览器可用的 Web 原型；只有当触键延迟、后台音频或 MIDI 外设需求明确时，再评估原生音频模块。

资料：
- OSMD：https://opensheetmusicdisplay.github.io/classdoc/
- MusicXML：https://www.w3.org/2021/06/musicxml40/
- Tone.js Sampler：https://tonejs.github.io/docs/15.1.22/classes/Sampler.html
- MDN Web Audio：https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API

## 七、实施阶段与验收

### 第一阶段：可点、可听的交互原型

- 横屏乐谱 + 键盘 + 基本控件真实可操作；含内置合法示例曲。
- 点击琴键真实发声；点击小节从对应位置开始试听；选 5–8 小节循环；暂停与重练生效。
- 用户用 Android 手机浏览器固定预览链接直接测试，不用安装 APK。

### 第二阶段：结构化学谱闭环（P0 正式完成）

- 真实导入 MusicXML/MXL；声部可选；五线谱正确渲染；固定唱名/音名辅助；可按小节练习。
- 三种模式完整可操作；0.5×、0.75×、1.0×、1.25× 生效；反复切换、暂停、旋转设备不发生状态错乱。
- 练习进度保存；反馈能包含真实版本和小节上下文；有自动化测试及手机手动验收记录。

### 第三阶段（P1，不作为本轮阻塞项）

- 简谱正式切换、MIDI 导入、和弦/左右手练习、节拍器/预备拍、外接 MIDI 键盘、更加准确的触键反馈。PDF 图片识谱和歌曲自动转谱仍属更后续阶段。

### P0 可执行测试清单

1. 手机浏览器打开真实部署 URL，加载示例谱，不是静态设计图。
2. 导入一份带至少 8 小节、3/4 或 4/4 拍的 MusicXML，能看到小节与音符。
3. 点击第 5 小节只选择并试听第 5 小节；点“选择范围”再依次选择第 5、8 小节，完整循环第 5–8 小节。
4. 0.75× 下音符音高不变；改速后选择区间仍正确。
5. 等待弹对模式：错键不推进、正确键推进；连续完成多个音符进入下一小节，范围完成后按循环设置重练。
6. 自由弹奏模式可触发琴键声音，至少双指同时按琴键，不出现长时间挂音。
7. 切换模式、切换声部、暂停/恢复、锁屏或切后台后界面与音频状态合理，无旧音频继续乱响。
8. 刷新页面仍可恢复本地练习进度；反馈能带上真实 commit/构建版本和当前小节，不泄漏原始谱文件。
9. 至少包含解析/事件映射/循环区间/等待弹对判断等单元测试，并有 GitHub Actions 运行记录。
10. 提供可复现的真实测试结果，对暂不支持的复杂乐谱明确标注限制。
