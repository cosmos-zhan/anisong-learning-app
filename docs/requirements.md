## 2. P0 功能范围：只做歌词循环学唱

### 2.1 主界面
以手机竖屏为主要设计目标，包含：歌曲标题/音频加载入口、滚动歌词区、选中范围高亮、播放/暂停、上一句/下一句、当前片段进度、0.5×/0.75×/1× 变速、循环开关、片段边界微调、反馈入口、版本信息。暂不开发钢琴、打分、人声分离、账号、社区或大模型语法教学。

### 2.2 歌曲与歌词输入
- 支持用户从手机本地选取合法持有的音频文件（优先 MP3/M4A/WAV，按实际浏览器支持情况提示），并导入标准 LRC 文件；提供可重复使用的**开源或自制测试音频与对应 LRC**，首次打开无需用户上传文件也能试用。
- 歌词按行呈现，内部时间轴采用音频**原曲时间**。优先使用 LRC 行时间戳；每行结束位置暂由下一行起点推算，可人工修正；最后一行使用音频结束时间或手动指定。
- 若歌词缺时间、时间乱序、超出音频长度，给出可理解的提示，不静默失败。对重复时间戳、空行、前后奏、相邻歌词间停顿做合理处理。
- 本地选择的音频默认在设备/浏览器本地处理，不上传到服务器；页面刷新后若文件句柄失效，提示重新选择，不谎称已永久保存。

### 2.3 歌词片段交互（核心）
- **单句模式**：点任意歌词行，立即从该句起点开始播放；若循环开启，直到用户暂停/切换才停止，不播放到下一句。
- **多句模式**：用户先点起始句，再点结束句，循环包含中间所有行的**连续音频**；区间可以反向选择，范围始终按照时间排序。选择时 UI 明确显示当前步骤，可取消。
- 第 2 句默认演示：文本「いつまでも覚えていたい」，原曲 `[16.3s, 21.1s)`，0.75×，循环开启；每轮理论耗时 6.4 秒（不含解码或重播延迟）。示例歌曲与该歌词仅作为界面演示数据，正式测试音频的歌词/时间戳必须真实匹配。
- 播放与暂停：暂停后继续从片段当前进度；停止（如实现）则回到片段起点；点击上一句/下一句后立即进入新片段。用户手动拖进度条，只在当前片段内定位。
- 关闭循环：当前选定片段播放完后停止，不自动进入后续整首歌曲；将来可单独增加“连续播放模式”。
- 起止边界可按 0.1 秒步长微调，不能小于 0、不能大于音频长度，且结束必须晚于开始。UI 同步展示准确数值。
- 改变速度后不改变原曲时间坐标；必须尽可能保留音高；速度选项至少 0.5×、0.75×、1×。UI 需区分真实音频播放与仅模拟的原型，不允许假按钮或伪造播放成功。

### 2.4 必须妥善处理的情况
- 片段终点回跳时暂停；用户快速连续切换歌词；重复点击播放；切歌时仍有旧音频加载任务；网络/文件读取失败；手机切入后台或被来电中断；歌词结束时间越界；超短无效片段。
- 控制逻辑使用独立状态机/Controller，确保旧异步任务不会覆盖新选择；UI 不通过低频刷新事件决定音频循环边界。
- 第一版网页可使用 Web Audio 或浏览器音频 API 做诚实的可用原型，记录并说明普通网页循环的精度局限。后续 Android 版优先验证 Media3 裁剪 + 单媒体项重复；不要未经测量承诺无缝、采样级精确循环。

## 3. 技术方案与代码结构
优先使用**单一共享前端 + 两个播放适配器**，最大化 UI 和业务代码复用：
- 前端：React + TypeScript + Vite，适配 Android 手机屏幕；必要时支持 PWA 安装，但不要求 PWA 才能使用。
- 音频抽象：`AudioEngine` 接口（load、setRange、setSpeed、play、pause、seek、getPosition、事件监听）；Web 适配器与 Android 原生适配器分别实现。
- 原生容器：Capacitor Android；如标准 WebView 音频不能满足片段循环体验，则编写 Kotlin/Media3 自定义插件接入 `AudioEngine`。
- 业务模块：Lyric/LRC Parser、Range Selector、Loop Controller、Player State、Feedback/Diagnostics；避免把控制逻辑塞进单个 UI 组件。
- 本地练习数据可先使用浏览器存储/Android 本地存储，按需进行轻量持久化；不要在 P0 引入云账号或复杂后端。

建议结构（可按实际技术栈调整，须在 README 解释）：
```
apps/web/                  # React/Vite 入口与 UI
apps/android/              # Capacitor / Android 容器及原生音频桥
packages/core/             # 歌词解析、时间范围、循环状态机、类型
packages/audio-web/        # Web AudioEngine
packages/audio-native/     # Android 桥接接口或适配器
.github/workflows/         # lint/test/build/web preview/android apk
.github/ISSUE_TEMPLATE/    # Bug、体验建议模板
public/demo/               # 可合法再分发的演示音频与歌词
scripts/                   # 构建和验证脚本
docs/                      # 运行、测试、反馈、维护、已知限制
```

## 7. 自动化测试与手工验收
核心自动测试必须覆盖：
- LRC 解析、无效/缺失时间戳、最后一句时长、重叠时间与多句时间区间计算。
- 第 2 行选择后正确得到 16.3–21.1 秒；0.75× 下保持基于原曲的时间坐标；打开循环后到边界回到起点。
- 选中第 2–4 行播放连续范围；暂停/恢复；关闭循环后片段结束停止；切换歌词时旧异步事件不干扰新片段；边界微调范围校验。

2. 点击任意一行，听到该行重复播放；多句模式可以循环连续范围。
3. 切换 0.75× / 1×、暂停继续、调整时间边界，UI 与实际音频一致。
4. 在 App 内填写反馈，跳转至预填 Issue 或复制完整报告，包含准确的测试版本。
5. Work 修改某个问题并提交 PR 后，我能通过新的预览链接验证；确认后可合并稳定版本。
6. 从 GitHub Actions 下载并安装 Android debug APK，重复测试本地文件、歌词选择及循环播放。
