# UI R1 钢琴谱面与横屏比例（0.3.4）

对照已确认 R1 第9页「横屏钢琴：谱、控制和琴键同时可见」。本批只修钢琴练习的谱面与尺寸，不修改歌词播放行为。

## 差异与调整

| 旧实现与稿的差异 | 本批实现 |
| --- | --- |
| 固定800px排版、8小节、双向滚动，实际谱面与可用高度脱节 | 默认4小节单行；谱面内部可用宽度不足560px或高度不足84px时2小节。独立翻页，播放按真实当前音符自动翻页。 |
| 整个多谱表声部一起挤进顶部，选中轨道的音符变得很小 | OSMD只显示当前练习谱表，保留同谱表真实多声部、和弦、谱号、调号、拍号、速度和装饰。播放模型与MusicXML不改写，不删除其他声部数据。 |
| 谱与琴键等高，顶部间距、边距不符合稿中布局 | 844×390无额外安全区时：标题52、谱136、控制44、状态24、琴键102px；间距6，左右20，上下4px。谱与琴键4:3分配余高。 |
| 横屏短视口被旧通用样式覆盖；字体和谱面坐标不一起缩放 | 新练习页样式优先于旧工作台媒体查询。≤360px高横屏用44px标题、20px状态、4px间距。SVG与点击区域 / 音名同一个等比变换，旋转不重置控制器。 |
| 选中区间上下粗线，当前小节不清楚 | 纸色谱面、浅绿范围、当前小节左侧绿色标记，真实当前音符高亮。 |

未将设计稿示意音符复制成静态谱。精细谱失败时仍有明确兼容提示和重试入口。为实际140小节翻页保留两侧44px触控按钮与顶部小字；这比稿中无翻页控件多出一行说明。谱表选择仍在齿轮面板。

## 固定交付门槛

用户要求每次修改完整构建 App，已写入 AGENTS.md、README、工作流和 `npm run android:check`。包括纯CSS修改：前端类型 / Lint / 全套测试 / production构建 → 两项实际构建ESM交互校验 → Capacitor同步 → Gradle原生测试与debug APK。最终交付提交必须通过，不以之前版本的APK或仅Vite构建代替。私有媒体继续不进GitHub，普通CI使用合法示例。

## 验证范围

新增测试检查真实双谱表 MusicXML 选择下谱表后仍正确映射全局小节和原始音符ID；旋转尺寸变化统一缩放SVG与点击层、不重启音频；短视口两小节分页；原有等待弹对、原轨和弦、歌词seek和原生循环坐标回归继续执行。生产产物检查实际加载OSMD及真实合成器调度，但使用jsdom与Web Audio仪器化边界，不能称为浏览器试听或手机截图验收。

实际完整构建结果以对应提交CI、交付回复与APK验证为准。当前会话无浏览器控制技能、物理Android或听音设备，未宣称像素对齐、Android16旋转、音色或多点触控已通过真机验收。

## 手机验收

1. 打开现有测试站 → 春日影 → 钢琴练习，核对关于 / 反馈版本0.3.4，横过手机。
2. 谱面、控制带、白黑键应同时出现，谱字保持比例；观察浏览器地址栏展开 / 收起、系统手势区与挖孔边缘。
3. 正常横屏显示4小节，短窄视口2小节。左右翻页不开始播放；点任一真实小节应立即试听；自动播放到下一页应跟随。
4. 齿轮选择另一谱表（如钢琴低音轨），确认只显示所选谱表，调号 / 拍号仍在；谱上点击位置与可见小节一致。
5. 选5–8小节 → 播放 / 暂停 / 重练 / 0.75倍 / 循环，检查声音；旋转后范围和速度保持。
6. 切等待弹对（含和弦须明确选择单音简化），错键不前进、对键前进；检查当前音符 / 小节高亮。
7. 同时按两个琴键再分别松开；进入学唱点一句，确认实际从该句起播。
8. 反馈请注明浏览器或APK、屏幕旋转状态、是否地址栏展开，并附真实版本。未经这一步不标记手机验收通过。
